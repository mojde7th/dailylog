قراردادهایی که اگر نفهمی، اپ را نمی‌توانی خودت جلو ببری

این کارگاه آموزش «وب چیست» نیست. فرض این است که HTML و جاوااسکریپت را بلدی. اینجا می‌گوییم چرا این پروژه این‌طور ساخته شده، هر بلوک کد برای چیست، و اگر خطی را عوض کنی چه می‌شکند.

الگو در هر فصل یکی است: اول هدف، بعد کل بلوک، بعد دلیل. شناسه‌ها داخل code می‌مانند؛ جمله را تکه نمی‌کنیم.

Code.gs را در گیت نگذار. کلید و شناسهٔ شیت فقط همان‌جا است.

چهار لایه، نه یک سایت

هدف: بدانی داده کجا حقیقت است، و گیت‌هاب فقط ویترین است.
phone / desktop
  index.html  ← DOM IDs = ABI برای app.js
  app.js      ← منطق، بدون bundler
  sw.js       ← فقط GET همین مبدأ، network-first
  IndexedDB   ← sessions (append) + meta (upsert روی تاریخ شمسی)
       │  آنلاین
       ▼
  POST text/plain JSON  →  Apps Script /exec
       │  اگر SCRIPT_VERSION یکی باشد
       ▼
  Sheet: SESSIONS · META · LAWS
         GOZARESH_*  مشتق است، منبع حقیقت نیست

Pages فقط فایل استاتیک پخش می‌کند. اگر Pages بخوابد، PWA نصب‌شده از کش می‌آید و ثبت‌ها در IndexedDB می‌مانند. صف وقتی نت برگردد خالی می‌شود. سرور خودت وسط این مسیر نیست.

قرارداد پرونده‌ها

هدف: بدانی کدام فایل را برای چه دست می‌زنی، و سه نسخه چرا باید با هم بالا بروند.
index.html     اسکلت + idها. برچسب فارسی آزاد است؛ id را نشکن.
app.js         تمام منطق. ES2017، بدون build.
sw.js          CACHE را عوض کن وگرنه فایل کهنه می‌ماند.
manifest.json  display:standalone + آیکون‌ها → نصب به‌عنوان برنامه.
Code.gs        محلی. VERSION باید با SCRIPT_VERSION یکی باشد.

APP_VERSION      روی کپسول اپ — فقط نمایش
app.js?v=56      کش مرورگر برای خود اسکریپت
CACHE            نام جعبه در Cache Storage
SCRIPT_VERSION   قفل با شیت — اگر نخواند، POST رد می‌شود

اگر فقط عنوان اپ را عوض کنی و ?v= و CACHE را نه، بعضی کلاینت‌ها هفته‌ها app.js کهنه می‌دهند. سه تای اول با هم. چهارمی فقط وقتی مدل شیت عوض شود.

display: standalone نوار آدرس را برمی‌دارد. آیکون ۱۹۲ و ۵۱۲ برای کاشی ویندوز؛ favicon.svg برای زبانه. اتصال در HTML فقط همین است:

<link rel="manifest" href="manifest.json"/>

service worker — خط‌به‌خط، زخمی که خوردیم

هدف: آفلاین برای فایل‌های خودت. همگام‌سازی شیت را هرگز قاپیدن.
const CACHE = 'dailylog-v58';

self.addEventListener('fetch', ev => {
  const req = ev.request;
  if (req.method !== 'GET') return;
  if (!req.url.startsWith(self.location.origin)) return;
  ev.respondWith(
    fetch(req).then(res => {
      const copy = res.clone();
      caches.open(CACHE).then(c => c.put(req, copy));
      return res;
    }).catch(() => caches.match(req))
  );
});

شرط متد: POST به گوگل از این handler رد می‌شود و به شبکهٔ واقعی می‌رود. اگر نبود، SW یا کشش می‌کرد یا شکست می‌داد.

شرط مبدأ: نشانی /exec روی دامنهٔ گوگل است. SW فقط origin همین Pages را لمس می‌کند.

ترتیب: اول شبکه، بعد کش. cache-first یک‌بار app.js کهنه را برای همیشه قفل کرد؛ تاریخ امروز و پیش‌فرض‌های جدید دیده نمی‌شد. برای همین network-first است.

skipWaiting و clients.claim نسخهٔ جدید را همان نشست فعال می‌کنند. اگر کنترلر عوض شود، اپ یک‌بار reload می‌کند تا مخلوط کهنه و نو نماند.

دکمهٔ سخت‌تازه‌سازی در تب داده همهٔ cacheها و ثبت SW را می‌کشد. وقتی «پوش کردم ولی سایت کهنه است» اول آن، بعد صبر برای Pages.

IndexedDB — دو store، دو مدل

هدف: نوبت رویداد است، متا وضعیت روز است. قاطی‌شان نکن.
sessions  keyPath: uid          // هر خط یک رویداد، شناسه تصادفی
meta      keyPath: dateShamsi   // یک ردیف در روز، upsert

put(store, obj)   // نه add — همان کلید را overwrite می‌کند
metaUid(day) → 'meta-' + day    // پایدار، تا شیت روی تاریخ merge کند
uid()     → Date.now().toString(36) + '-' + random

put به‌جای add: ثبت دوبارهٔ همان روز متا، ردیف دوم نمی‌سازد. دفتر عمداً uid تصادفی دارد تا دو خط در یک میلی‌ثانیه هم برخورد نکنند.

نشانی شیت و کلید در localStorageاند نه در IDB. پاک‌کردن storeها تنظیمات را لزوماً نمی‌کشد. تب آخر هم همین‌جا است؛ برای همین برگشت از شیت نباید اجباری روی متا بیفتد.

در Application، کلید dl_tab را دستی data کن، رفرش. باید تب داده باز شود.

تاریخ شمسی به‌عنوان ABI، نه لوکال ویندوز

هدف: هر رکورد رشتهٔ صفرپَد باشد تا فیلتر بازه مقایسهٔ lexicographic باشد.
fmtJ(y, m, d) → '1405/05/30'
todayJ()      → از Date محلی، تبدیل ریاضی به جلالی — به locale ویندوز وصل نیست
addDaysJ      → جمع روی ماه‌های ۳۱/۳۰/۲۹، نه Gregorian setDate
dashSpan(7)   → از امروز منهای ۶ تا امروز، هر دو سر شامل

بدون صفر جلو ماه، 5/2 از 5/10 بزرگ‌تر دیده می‌شود. اگر امروز سی مرداد باشد هفت روز یعنی ۲۴ تا ۳۰، نه اول ماه. چرخ اسکرول تا در DOM ارتفاع نداشته باشد رویداد scroll را نادیده می‌گیرد؛ وگرنه scrollTop صفر روز اول ماه را برمی‌داشت. سال «امروز منهای دو» با همان ماه‌روز به امروز می‌چسبد چون حلقهٔ سال گاهی روی کپی اشتباه می‌نشست.

چرخ دفتر تنبل ساخته می‌شود تا قبل از اولین فریم کار اضافه نباشد. چرخ موس فقط بعد از کلیک روی همان ستون مسلح است.

const PARTS = [
  { id: 0, label: 'تا ۱۲' },
  { id: 1, label: '۱۲ تا ۲' },
  { id: 2, label: '۲ تا ۶' },
  { id: 3, label: 'بعد اوپن' }
];
CODES.filter(c => c.from <= selectedPartId)

کل پارت یک آرایه است. from یعنی از این پارت به بعد دیده شود. پارت ۲ کدهای ۰ و ۱ و ۲ را دارد. چهار لیست جدا ننویس.

چینش ردیف: اسم چپ، مدت راست. فینگلیش LTR. بازهٔ عددی مثل ۱۲ تا ۲ همان‌طور که نوشته شده می‌ماند. «بعد اوپن» RTL ایزوله است تا واژه‌ها قاطی نشوند. صفحه RTL است؛ اگر خود ردیف را RTL بگذاری، مدت می‌رود چپ.

متا — draft تا put ته گروه

هدف: انتخاب همه صف را پر نکند. یک put ته گروه، کل گروه را می‌نویسد.
flagDraft[id] = 1 | 0     // فقط حافظهٔ صفحه
flagOn(rec, id)           // اگر draft هست همان؛ وگرنه مقدار ذخیره‌شده

async function putGroup(gid) {
  // پرچم از draft، مدت اگر چرخ صفر نباشد جمع می‌شود
  rec.synced = 0;
  await put('meta', rec);
  trySync();
}

تا ثبت نزنی، IDB و شیت بی‌خبرند. synced = 0 یعنی حتی اگر قبلاً رفته باشد، این ویرایش دوباره صف می‌شود.

میانگین تأخیر: اگر زیر ۱٫۵ ثانیه شود پرچم انجام پاک می‌شود. یک نمونهٔ کوتاه میانگین را می‌کشد؛ عمدی است.

چند ردیف متا برای یک روز: metaFor پرترین را نگه می‌دارد، حفره را از بقیه پر می‌کند، اضافه را حذف می‌کند.

انتخاب همه در گروه اول. صف نباید زیاد شود. دو پرچم خاموش، بعد ثبت ته گروه. صف یک متا. برگشت روی یک پرچم در تب داده فقط همان تکه را برمی‌دارد.

دفتر — append-only و ارث

هدف: هر خط رویداد جدا. ادغام روی روز مال متا است نه دفتر.
const row = {
  uid: uid(),
  dateShamsi, partId, category, code,
  minutes, tags, note, synced: 0
};
await put('sessions', row);

کدهای stick در یک بلوک می‌مانند بدون برچسب دستهٔ تکراری. نوار پایین فقط دفتر است؛ متا ثبت خودش را ته گروه دارد.

قانون — بدون نسخهٔ جدید اپ برای هر نام

هدف: نام از پیش معلوم نیست. قالب خالی: نام، توضیح، مدت.
catalog     localStorage dl_law_catalog
lawDraft    تا put ته گروه صف نمی‌شود
lawsJson    روی همان ردیف META
tab LAWS    explode برای گزارش سطری

جیسان عکس همان روز است و با یک sync می‌آید. تب قانون برای فیلتر در شیت است. بعد از v11-meta، قانون تازه اسکریپت تازه نمی‌خواهد. ثبت تکی ندارد؛ ته گروه کل لیست را می‌نویسد.

چرا text/plain، چرا قفل نسخه

هدف: از Pages به گوگل بدون preflight، و هرگز ستون نو به اسکریپت کهنه.
headers: { 'Content-Type': 'text/plain;charset=utf-8' }
body: JSON.stringify({ secret, type, version, fields, rows })

if (trySync._busy) return;
if (String(outp.version) !== SCRIPT_VERSION) throw ...

دامنهٔ Pages ≠ دامنهٔ گوگل. اگر application/json بفرستی، مرورگر OPTIONS می‌زند و Apps Script آن را دوست ندارد. بدنه همان JSON است؛ نوع محتوا متن ساده است تا CORS ساده بماند.

قفل مشغول: دو sync موازی ردیف تکراری یا قفل شیت می‌ساخت. صف خالی فقط وقتی خودت دکمه زدی toast می‌دهد؛ همگام پس‌زمینه ساکت است.

بدنه آرایهٔ مقادیر به ترتیب فیلدها است، نه شیء آزاد. فیلد غایب رشتهٔ خالی می‌شود نه undefined، تا سلول شیت به‌هم نریزد.

Network، فیلتر exec. یک put گروه. بدنه باید type: "meta" و rows: [[...]] باشد. پاسخ باید همان v11-meta را برگرداند. اگر HTML ورود گوگل آمد، یا URL غلط است یا دسترسی اجرا برای همه نیست.

Apps Script — ویرایشگر، نه پنجرهٔ Deploy

هدف: کد را در editor بگذاری، ذخیره کنی، بعد روی همان /exec نسخهٔ جدید بسازی.
doGet()   VERSION + نام تب‌ها — دکمهٔ «نسخهٔ همین آدرس»
doPost()  secret، بعد upsert متا یا insert نوبت یا sessionDelete

var VERSION = 'v11-meta';

پنجرهٔ Deploy کد را اجرا نمی‌کند؛ فقط از روی editor ذخیره‌شده snapshot می‌گیرد. استقرار تازه یعنی URL تازه؛ اپ هنوز URL پیر را دارد.

rebuildReportsNow داخل خودش دکمه ندارد. از فهرست توابع انتخاب کن، Run. بار اول OAuth. برای عوض شدن ظاهر اپ لازم نیست این فایل را دست بزنی؛ قفل هنوز v11-meta است.

اگر سرستون متا نخواند، اسکریپت تب کهنه را آرشیو می‌کند و بازمی‌سازد. حذف دستی لازم نیست.
