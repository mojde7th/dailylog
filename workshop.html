سرویس‌ورکر خط‌به‌خط — زخمی که یک‌بار خوردیم

پرونده:

sw.js

کارگر در پس‌زمینه می‌نشیند و درخواست‌های گت را می‌قاپد. پست همگام‌سازی را نباید بقاپد وگرنه ارسال شیت خراب می‌شود.

self.addEventListener('fetch', ev => {
  const req = ev.request;
  if (req.method !== 'GET') return;
  if (!req.url.startsWith(self.location.origin)) return;
  ev.respondWith(
    fetch(req).then(res => {
      const copy = res.clone();
      caches.open(CACHE).then(c => c.put(req, copy));
      return res;
    }).catch(() => caches.match(req) ...)
  );
});

اثر خط اول شرط: پست به گوگل از این تابع رد می‌شود و به شبکهٔ واقعی می‌رود. اگر این شرط نبود، کارگر پست را هم کش می‌کرد یا شکست می‌داد.

/exec

پرترین را نگه می‌دارد، حفره‌ها را از بقیه پر می‌کند، بقیه را حذف می‌کند. مهاجرت نام‌های کهنه هم اینجاست: حالت روزهٔ قدیمی اگر «اوپن» داشت می‌شود پرچم ساعت‌کمتر‌از‌یک، ساعت بیداری اگر عددش پنج یا کمتر بود می‌شود پرچم، ساعت‌های عقربه اگر رشتهٔ ساعت بودند می‌شوند یک.

آزمایش: انتخاب همه در دستهٔ اول. صف را نگاه کن — نباید زیاد شود. دو پرچم را خاموش کن. ثبت ته دسته. حالا صف باید یک متا نشان بدهد نه ده‌ها. لغو روی یک پرچم در تب داده‌ها فقط همان تکه را برمی‌دارد نه کل روز.

دفتر نوبت — ارث پارت‌ها و خط لاتین

const codesForPart = p => CODES.filter(c => (c.from || 0) <= p);

اثر

from

: کار صبح از پارت صفر به بعد همه‌جا هست. کار مخصوص بعدازظهر فقط از پارت دو به بعد دیده می‌شود. آخر هفته را گذاشتیم از پارت دو تا در شلوغی صبح گم نشود.

چند کار که «باید سر هم باشند» ویژگی چسب دارند. برچسب دسته برای آن‌ها چاپ نمی‌شود تا سه دکمه یک بلوک شوند.

نقاشی دفتر: عنوان پارت راست‌به‌چپ فارسی است، خود خط چپ‌به‌راست مثل دفتر لاتین:

takhshose(tamrkzshadid,q=2.40):30m

کیفیت داخل پرانتز می‌ماند. چرخ «مدت همین کیفیت» اگر صفر نباشد

q=...

به برچسب اضافه می‌شود. تراشهٔ کیفیت را دوباره بزن تا خاموش شود؛ قبلاً فقط روشن می‌شد و اشتباه می‌ماند.

نوار پایین فقط روی دفتر است. متا ثبت خودش را ته دسته دارد. این کم کردن زمان ارسال بود: یک انگشت ته دسته، نه بیست ثبت جدا.

آزمایش: پارت تا دوازده را بزن. باید تخصیص را ببینی. پارت دو تا شش را بزن. تخصیص هنوز هست چون ارث است، به‌علاوه روان چسبیده. یک کیفیت بزن، همان را دوباره بزن. باید از جعبهٔ پرانتز حذف شود.

همگام‌سازی — چرا متن ساده، چرا قفل، چرا نسخه

headers: { 'Content-Type': 'text/plain;charset=utf-8' }
body: JSON.stringify(payload)

اثر نوع محتوا: درخواست از دامنهٔ گیت‌هاب به دامنهٔ گوگل، اگر جیسانِ واقعی باشد مرورگر اول گزینه‌پیش‌پرواز می‌فرستد و اسکریپت گوگل آن را دوست ندارد. متن ساده بدون آن رقص است، در حالی که بدنه همان جیسان است.

if (trySync._busy) return;

اثر: دو همگام‌سازی هم‌زمان ردیف تکراری یا خطای قفل گوگل می‌ساخت. یک پرچم مشغول کافی است.

صف خالی دیگر خطای قرمز نمی‌دهد مگر خودت دکمه را زده باشی.

if (!s.length && !m.length) {
  if (loud) toast('صف خالی است');
  return;
}

قبلاً حتی پرس‌وجوی خاموش هم گاهی «ارسال نشد» نشان می‌داد. الان پرس‌وجوی پس‌زمینه ساکت است.

if (String(outp.version) !== SCRIPT_VERSION) throw ...

اثر: اپ ستون‌های جدید را به اسکریپت کهنه نمی‌فرستد تا شیت را خراب نکند. پیام «وب‌اپ کهنه است نه گیت‌هاب» یعنی ویترین نو است، انبار ابری نه.

بدنهٔ ارسال: به‌جای شیء، آرایهٔ مقادیر به ترتیب فیلدها. اسکریپت همان ترتیب را به ستون‌ها نقشه می‌کند. اگر فیلد در ردیف نباشد رشتهٔ خالی می‌رود نه

undefined

تا سلول شیت به‌هم نریزد.

آزمایش: اف۱۲، شبکه، فیلتر

exec

یک ثبت دسته بزن. پست را باز کن. باید

type: "meta"
fields: [ ... ]
rows: [ [ ... ] ]

باشد. پاسخ باید نسخهٔ اسکریپت را برگرداند. اگر اچ‌تی‌ام‌ال ورود گوگل آمد، یا نشانی استقرار غلط است یا دسترسی اجرا برای همه نیست.

اسکریپت گوگل — ویرایشگر نه مدیریت استقرار

پروندهٔ محلی:

D:\tech-lab\habit-pwa\Code.gs

این را در گیت نگذار. کلید آنجاست.

دو ورودی:

doGet()   نسخه، نام تب‌ها، سرستون متا — برای دکمهٔ «نسخهٔ همین آدرس»
doPost()  احراز، بعد upsert متا یا درج نوبت

متا ادغام روی تاریخ شمسی است نه همیشه ردیف جدید. نوبت‌ها اگر شناسه تکراری باشد رد می‌شوند.

بزرگ‌ترین اشتباه عملی که خوردیم: کد را در مدیریت استقرار گذاشتن. آنجا کد اجرا نمی‌شود. آنجا فقط نسخه از روی ویرایشگر ذخیره‌شده ساخته می‌شود.

  1. اسکریپت را باز کن.
  2. کل متن ویرایشگر را با پروندهٔ محلی عوض کن.
  3. در ویرایشگر باید ببینی:
var VERSION = 'v8-meta';
  1. ذخیره.
  2. استقرار، مدیریت استقرار، مداد روی همان وب‌اپی که نشانی‌اش در تب داده‌ها است، نسخهٔ جدید. استقرار تازه نساز.
  3. همان لینک اجرا را در تب خام باز کن. باید جیسان با همان نسخه بیاید.

اگر استقرار تازه بسازی، نشانی عوض می‌شود. اپ هنوز نشانی پیر را دارد و پیر هنوز نسخهٔ کهنه را می‌دهد. دقیقاً همان وضعیت «آمده نسخهٔ هفت، باید هشت».

بعد از عوض شدن ستون‌ها، اسکریپت تب متا را اگر سرستون نخواند با آرشیو و بازسازی هم‌تراز می‌کند. تب کهنه را حذف نمی‌کند؛ اسمش را عوض می‌کند. داده نمی‌پرد، اما یک‌بار باید نسخهٔ جدید واقعاً اجرا شود.

دیباگ‌هایی که واقعاً خوردیم — نسخهٔ قابل تجربه

یک — سایت کهنه بعد از پوش

علت: کش‌اول. درمان: شبکه‌اول، نام کش، پارامتر نسخه روی اسکریپت، دکمهٔ سخت‌تازه‌سازی. تجربه: در کارگر نام کش را دستی در اف۱۲ پاک کن، رفرش، باید پروندهٔ نو بیاید.

دو — شیت کهنه در حالی که گیت‌هاب نو است

علت: ویرایشگر ذخیره نشده یا مداد روی استقرار دیگر. تجربه: لینک اجرا را باز کن. اگر نسخهٔ هفت دیدی، اپ درست می‌گوید. دروغ نمی‌گوید.

سه — ارسال نشد دروغین

علت: همگام‌سازی خاموش هم خطا را برشته می‌کرد؛ صف خالی خطا بود؛ دو فراخوانی موازی. درمان: فقط وقتی خودت زدی برشته؛ قفل مشغول؛ صف خالی آرام.
